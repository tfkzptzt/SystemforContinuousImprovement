# 高校课程持续改进系统

面向高校课程考核的持续改进全流程管理系统：教师上传课程考核报告 → 系统自动剖析生成改进措施 → 提交专业负责人审批并指派责任人 → **每条措施分发给对应责任人，责任人逐条填写达成报告、随交随审** → 负责人逐份通过/打回 → **全部达成报告通过后负责人对整份报告一次性四级定级**，同时支持历史报告批量导入与新学年循环改进。

## 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | Python 3.14 + Flask 3.x（Blueprint 模块化路由） |
| 前端 | Vue 3（本地挂载 CDN/全局构建）+ Vue Router（hash 路由）单页应用，纯 JS 组件 |
| 数据库 | SQLite（标准库 `sqlite3`，无 ORM），`schema.sql` 定义结构 |
| 文件解析 | docx 文本抽取（`zipfile` + `xml.etree` 标准库实现）；Excel 导入/导出（`openpyxl`） |
| 外部依赖 | 仅 `Flask`、`openpyxl`、`Werkzeug`（随 Flask 安装） |

## 快速启动

```powershell
# 1. 安装依赖（如未安装），依赖见 requirements.txt（宝塔面板Python项目管理器可自动安装）
pip install flask openpyxl

# 2. 初始化数据库并写入种子数据（幂等，可重复执行）
python seed.py

# 3. 启动服务
python app.py
```

浏览器访问 <http://127.0.0.1:5000>。

> ⚠️ 本次上线达成报告按措施一对一改造，数据库结构有重大变更：`achievements` 表重构为逐措施关联、`reports` 表新增 `conclusion`/`concluded_at`、新增 `settings` 配置表。升级旧库需删除 `data.db` 后重跑 `python seed.py`（注意会清空业务数据与 `uploads/` 下的已上传文件）。

## 管理后台

`admin01` 登录后直接进入管理后台，提供：

- **用户管理**：新建用户（密码留空则自动生成随机初始密码）、重置密码（重置为随机新密码，仅显示一次，需当场记录）、批量导入用户（可下载「用户名 ↔ 初始密码」对照表，30 分钟内有效）、分配工作端（教师端 / 专业负责人端 / 可同时拥有）、停用/启用账号；删除用户需双重确认。
- **安全选项**：开启/关闭「首次登录强制修改初始密码」、设置登录失败最大尝试次数与临时封锁时长、查看密码最短长度（8 位）。
- **学年管理**：维护学年，每学年固定包含第一学期/第二学期。
- **课程管理**：新建课程（含起止时间）、指派专业负责人；该课程报告的审批将定向发送给指派的负责人。
- **AI 配置**：管理大模型接口配置（启用开关、API Key、Base URL、模型、超时、系统提示词），支持「测试连接」验证配置有效性。配置优先级：**数据库 > 环境变量 > 默认值**；API Key 只写不读（仅显示掩码）；未配置或 AI 调用失败时自动回退内置规则引擎。


## 接入 AI 大模型生成措施（可选）

「生成改进措施」默认使用内置规则引擎（从报告正文抽取，无需任何外部服务）。系统同时支持接入**通用 OpenAI 兼容大模型**，启用后采取 **AI 优先 + 规则引擎兜底** 策略：配置了密钥则调用大模型生成，未配置或调用失败（网络/超时/解析异常）时**自动静默降级**到规则引擎，用户无感知。

**配置优先级：数据库（管理后台 AI 配置页）> 环境变量 > 默认值**。管理员可在后台「AI 配置」页面在线设置，也可通过环境变量配置（`config.py` 读取），**不配置任何变量时行为与纯规则引擎版本完全一致**：

| 环境变量 | 说明 | 默认值 |
| --- | --- | --- |
| `AI_API_KEY` | 大模型 API 密钥；**为空即视为未启用 AI**，直接走规则引擎 | 空（未启用） |
| `AI_BASE_URL` | OpenAI 兼容服务的 base url（**不带** `/chat/completions`，系统自动拼接） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `AI_MODEL` | 模型名 | `qwen-plus` |
| `AI_TIMEOUT` | 单次请求超时（**必须为纯数字秒**，非法值如空串/`30s`/负数将被忽略并回落默认值） | `60` |
| `AI_ENABLE_THINKING` | 是否开启模型思考模式（`1`/`true`/`yes`/`on` 视为开启）。开启后模型先输出推理过程再给答案，非流式调用耗时成倍增长，**建议保持关闭** | 关闭 |

> 「OpenAI 兼容」指服务商提供与 OpenAI 相同的 `POST {base_url}/chat/completions` 接口与请求/响应结构（`Authorization: Bearer <key>`、`messages`、`choices[0].message.content`）。阿里云百炼、DeepSeek、Moonshot、本地 vLLM/Ollama 等均提供此兼容端点。

**示例一：阿里云百炼（通义千问，默认值即为此，仅需设置密钥）**

```powershell
$env:AI_API_KEY = "sk-你的百炼密钥"
# 以下与默认一致，可省略
$env:AI_BASE_URL = "https://dashscope.aliyuncs.com/compatible-mode/v1"
$env:AI_MODEL    = "qwen-plus"
```

**示例二：DeepSeek**

```powershell
$env:AI_API_KEY  = "sk-你的DeepSeek密钥"
$env:AI_BASE_URL = "https://api.deepseek.com"
$env:AI_MODEL    = "deepseek-chat"
```

设置后正常 `python app.py` 启动即生效。安全提示：

- **后台配置会将密钥明文存于 `data.db` 的 `settings` 表**（配置优先级 DB > env > default）。启用后台配置后须把 `data.db` 视为敏感文件：勿提交 Git、备份需加密。若仅使用环境变量注入，保持 DB 中 `ai_api_key` 为空即可（后台「清除密钥」按钮可清空）。
- 日志与异常信息中一律不会出现密钥明文；后台 API 仅返回掩码（`******`）。
- 宝塔面板部署时，在「Python 项目管理器 → 项目环境变量」中设置以上变量后重启项目即可。
- **启用 AI 后须按整条链路调大超时**：默认提示词要求 3-4 条措施、每条 content 60-120 字并含量化验证指标（输出约 700 token）。耗时完全取决于端点吞吐：公共 DashScope 约 20-50 秒，专属 MaaS 部署实测约 8 token/s、需 85 秒以上。`AI_TIMEOUT` 默认 60s，用专属端点时在后台调到 120。三处取值必须递增：`AI_TIMEOUT < gunicorn --timeout < Nginx proxy_read_timeout`（例如 120 < 150 < 200），否则上游先掐断只会得到 502。推荐启动参数 `gunicorn app:app --timeout 150 --workers 1 --threads 4`：长请求只占用一个线程而非整个进程，且单进程可让登录限速（`memory://` 按进程计数）保持精确。AI 调用超时**不会向前端报错**，后端会静默降级到规则引擎（产出较通用），服务端日志留一条 `AI 生成失败，降级到规则引擎`。
- **思考模式默认关闭，可在后台开启**：后台「AI 配置 → 思考模式」开关（环境变量 `AI_ENABLE_THINKING` 为兜底），配置优先级同样是 DB > env > 默认。开启后模型会先输出一大段推理再给答案，本系统是非流式调用，必须等推理全部生成完才能拿到结果，耗时可能成倍增长并触发超时降级——改进措施生成不需要推理链，一般保持关闭。该开关是 DashScope/百炼专有参数，**仅当 Base URL 主机名属于 `aliyuncs.com` 时才随请求下发**（其他兼容服务可能把未知字段当错误拒绝），判定逻辑见 `services/ai_generator.py:_is_dashscope`。
- 生成来源仅在**本次由 AI 成功生成**时记录到操作日志的 `generate_source` 字段（值为 `ai`）；走规则引擎（未启用或降级）时不写该字段，避免审计日志/时间线出现恒定噪声。


## 完整演示剧本

对应业务主流程「新建报告 → 生成措施 → 提交 → 审批分配责任人 → 责任人逐条填写达成 → 负责人逐份审核 → 全部通过后整体定级 → 记录查询 → 批量导入 → 新学年继续」：

> 前置提示：管理员（`admin01`）可先在管理后台指派课程负责人；种子数据已将所有课程负责人指派为 `leader01`。

1. **新建报告**（`teacher01` 登录）：仪表盘 → 「新建报告」，选择课程（如 工程制图 2025-2026学年第一学期），上传 `samples\工程制图课程目标达成情况分析报告_2024-2025-1.docx`。
2. **生成措施**：新报告处于「草稿」状态，点击「去生成措施」，系统自动从报告正文抽取改进措施与次年验证指标（过滤章节标题噪声），可逐条编辑、增删。（若已配置 AI，此步优先由大模型生成，失败自动回退规则引擎。）
3. **提交审批**：点击「提交专业负责人审批」，状态变为「待审批」。
4. **审批并分配责任人**（换 `leader01` 登录）：负责人仪表盘 → 待审批列表中打开该报告，逐条指派责任人（限启用中的教师）并设置截止时间，「审批通过」后报告直接进入「执行中」状态；若不满意可填写原因「退回」，教师修改后可重新提交。
5. **责任人填写达成**（各责任教师）：教师端顶栏「我的任务」→ 查看分配给自己的措施列表，点击「填写达成」逐条提交达成报告；被打回的措施显示打回原因，修改后重新提交。
6. **负责人逐份审核**（`leader01`）：待审达成列表中显示每份报告的达成进度（已提交/总措施数），点击进入审核页，逐条措施「通过」或「打回」（需填写原因）。
7. **整体定级**（`leader01`）：全部措施达成报告通过后，审核页底部出现「整体定级」区，从四级结论中选择：已达成目标 / 基本达成目标 / 部分达成目标 / 未达成目标，流程闭环（状态「已定级」）。
8. **记录查询**：任意角色进入「历史查询」，可按课程/学年/教师检索已导入或已完成的报告，查看完整记录详情（逐措施达成情况、结论、退回记录、操作时间线）。
9. **批量导入**（`leader01`）：「批量导入」页可先下载导入模板，再上传 `samples\历史报告导入_2021-2024.xlsx` 一键导入 2021-2024 三个学年的历史持续改进记录，页面逐行反馈成功/失败原因。
10. **新学年继续**：新学年开课后，教师针对同一课程上传新的考核报告，重复步骤 1-7，形成「评价—改进—验证」的循环；上一轮改进措施的执行结果可在新报告中对照验证。

### 报告删除规则

教师仅可删除自己创建的、状态为「草稿 / 已生成措施 / 已退回」的报告（即尚未提交审批或已被退回的报告）。删除操作不可撤销，将同时级联删除已生成的措施与上传的文件。已进入审批流程（待审批/执行中/已定级）的报告不可删除。

## 批量导入模板说明

模板可从「批量导入」页下载（接口 `GET /api/import/template`），列结构固定（首行表头）：

| 列 | 说明 | 示例 |
| --- | --- | --- |
| 教师工号 | 系统内教师用户名 | teacher01 |
| 课程代码 | 课程代码 | GCTZ1001 |
| 学年 | 格式「YYYY-YYYY学年」 | 2021-2022学年 |
| 学期 | 第一学期 / 第二学期 | 第一学期 |
| 报告标题 | 导入报告的标题 | 工程制图课程持续改进报告 |
| 措施内容 | 当年改进措施 | 引入习题课集中讲评与错题归因分析… |
| 验证指标 | 次年验证指标 | 通过下一学年期中考试投影章节得分率… |
| 结论 | 四级结论之一 | 已达成目标 / 基本达成目标 / 部分达成目标 / 未达成目标 |

约束：教师工号与「课程代码+学年+学期」必须在系统字典中存在，结论必须为四级结论之一，否则该行导入失败并给出原因。`samples\历史报告导入_2021-2024.xlsx` 即为可直接导入的完整示例。

├── db.py                   # 数据库连接/建库/公共查询/操作日志
├── schema.sql              # 数据库结构
├── seed.py                 # 建库 + 种子用户/课程（幂等）
├── auth.py                 # 登录、会话与角色鉴权
├── api_reports.py          # 教师端：报告上传/列表/详情/删除/措施生成编辑/提交/改截止/按措施提交达成/我的任务
├── api_approvals.py        # 负责人端：待办/审批通过/退回/逐份达成审核(通过/打回)/整体定级
├── api_admin.py            # 字典、批量导入、导入模板下载、日志查询
├── api_manage.py           # 管理后台：用户管理、学年管理、课程管理、AI 配置
├── data.db                 # SQLite 数据库文件（由 seed.py 生成）
├── services/
│   ├── __init__.py         # 包初始化
│   ├── docx_extract.py     # docx 纯文本抽取（标准库实现）
│   ├── measure_generator.py# 规则式改进措施生成（含章节标题噪声过滤）

│   ├── importer.py         # Excel/CSV 批量导入 + 导入模板生成
│   └── state_machine.py    # 报告状态机（唯一状态存于 reports.status）
